The Problem

Why does this system exist?

📋

Manual Record Keeping

Attendance is tracked on paper registers which are prone to loss, damage, and human error.

🔍

No Easy Reporting

Generating attendance summaries or identifying absent students requires manual counting.

🏫

No Centralised Data

Student, teacher, and course data is scattered across different registers and spreadsheets.

⏱️

Time Consuming

Teachers spend valuable class time calling registers instead of teaching.

03 / 10
The Solution

What we built

  • A centralised web platform accessible from any browser
  • Full CRUD management for students, teachers, and courses
  • Attendance recording with Present / Absent / Late status
  • Real-time search and filtering across all records
  • Attendance reports with percentage statistics
  • Secure login system — all pages require authentication
  • Deployed live on Render — accessible anywhere

Features

Core Features

👨‍🎓

Student Management

Add, edit, delete students. Fields: username, full name, admission number, phone, gender.

👨‍🏫

Teacher Management

Add, edit, delete teachers. Fields: username, full name, employee number, department.

📚

Course Management

Add, edit, delete courses. Each course is assigned to a teacher.

✅

Attendance Recording

Mark students as Present, Absent, or Late per course per date. Prevents duplicate entries.

📊

Reports & Statistics

Filter by student, course, date, status. Shows totals and attendance percentage.

🔐

Authentication

All pages require login. Custom login/logout views with welcome messages.

REST API Endpoints

Endpoint Methods Description
/api/students/GET, POSTList all students / Create a student

/api/teachers/GET, POSTList all teachers / Create a teacher

/api/courses/GET, POSTList all courses / Create a course
/api/courses/<id>/GET, PUT, DELETERetrieve, update, or delete a course
/api/attendance/GET, POSTList all records / Create a record
/api/attendance/<id>/GET, PUT, DELETERetrieve, update, or delete a record

All endpoints are powered by Django REST Framework ModelViewSets with PageNumberPagination (page size: 10). The frontend uses a fetch_all() helper to automatically follow pagination links.

Deployment

Deployment on Render

⚙️

Backend Service

Start: gunicorn attendance_system.wsgi:application

Build: pip install -r requirements.txt

DB: PostgreSQL (Render managed)

🎨

Frontend Service

Start: gunicorn frontend_project.wsgi:application

Build: pip install -r requirements.txt && python manage.py collectstatic --noinput

Environment Variables

  • SECRET_KEY — Django secret key
  • DEBUG — Set to False in production
  • DATABASE_URL — PostgreSQL connection string
  • ALLOWED_HOSTS — Render domain

Static Files

Served by WhiteNoise with CompressedManifestStaticFilesStorage — no separate CDN needed.
